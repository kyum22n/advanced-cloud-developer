## 5. 삭제 완료 확인

`az group exists --name rg-advdev-lkm-data`를 30초 간격으로 폴링하여 확인했습니다.

| 항목 | 값 |
|---|---|
| 삭제 요청 시각(KST) | 16:23:27 |
| `exists` 폴링 결과 | 16:23:45 true → 16:24:16 true → 16:24:47 **false** |
| 삭제 완료 확인 시각(KST) | **16:24:47** |
| 소요 시간 | 약 1분 20초 |

삭제 완료 후 `az group list` 재조회 결과, 남은 리소스 그룹은 `NetworkWatcherRG` 하나뿐이며, `az group exists --name rg-advdev-lkm-data` 결과도 **false**로 최종 확인했습니다.

## 6. 비용 확인 방법

### 포털에서 확인

**[비용 관리 + 청구] → [비용 분석]**에서 구독을 선택하고, 기간을 이번 1차시 실습 기간(오늘 포함)으로 설정하면 서비스별(스토리지/MySQL/Log Analytics/네트워킹 등) 비용 내역을 그래프와 표로 볼 수 있습니다. 리소스 그룹 단위로 필터링하면 `rg-advdev-lkm`, `rg-advdev-lkm-data`에서 발생한 비용만 따로 볼 수 있습니다.

### CLI로 확인

```
az consumption usage list --start-date <YYYY-MM-DD> --end-date <YYYY-MM-DD> --output table
```

리소스 그룹·서비스별로 사용량과 비용이 나열됩니다.

### ⚠️ 시차 주의

Azure의 사용량·비용 데이터는 **실시간으로 반영되지 않으며 보통 몇 시간~최대 1~2일의 지연**이 있을 수 있습니다. 리소스를 삭제한 직후에는 비용 화면에 아직 반영되지 않았거나 과소 표시될 수 있으므로, 실습 완료 다음 날 정도에 한 번 더 확인하는 것을 권장합니다.

## 7. 향후 비용 사고 방지를 위한 안전장치 제안

| 안전장치 | 설명 |
|---|---|
| 구독 예산(Budget) + 경고 설정 | [비용 관리 + 청구] → [예산]에서 월 한도(예: 5만원)를 설정하고 50%/80%/100% 도달 시 이메일 알림을 받도록 구성 — 방치된 리소스로 인한 과금 폭증을 조기에 인지 |
| 리소스 그룹 태그로 실습용 표시 | 모든 실습 리소스 그룹에 `env=lab`, `owner=lkm`, `expire=2026-08-31` 같은 태그를 일괄 부여하고, 정기적으로 태그 기준 조회(`az group list --tag env=lab`)해서 방치된 실습 그룹을 찾아 정리 |
| 자동 종료/삭제 스케줄 | VM은 [자동 종료] 기능으로 매일 특정 시각에 자동 종료하도록 설정하고, 리소스 그룹 전체는 Azure Automation 또는 Logic Apps로 "N일 경과 시 자동 삭제" 스케줄을 구성해 실습 종료 후 깜빡 잊고 방치되는 것을 방지 |
