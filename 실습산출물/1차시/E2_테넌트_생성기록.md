|---|---|

## 2. 실제 시도 결과 — **차단됨 (X)**

- 포털에서 검색창에 "Microsoft Entra ID" 입력 후 클릭 → **관리 화면 진입 단계에서 즉시 401 오류 발생**.
- 오류 내용:
  ```json
  {"sessionId":"c21064963be1433c8c312dd93e8aed3b","subscriptionId":"","resourceGroup":"","errorCode":"401","resourceName":"","details":"권한이 부족하여 작업을 완료할 수 없습니다."}
  ```
- 테넌트 생성은커녕 **Microsoft Entra ID 관리 센터 자체에 접근할 권한이 없음**을 확인 → 이후 단계(테넌트 유형 선택, 도메인 입력 등)는 시도 불가.

**원인 진단**: 위 사전 점검에서 확인했듯 이 계정은 디렉터리 역할이 전혀 없는 일반 구성원(member) 계정입니다. 신한대학교 조직 테넌트가 학생/일반 사용자 계정에 대해 Microsoft Entra 관리자 센터 접근 및 테넌트 생성 권한을 조직 정책으로 제한하고 있는 것으로 판단됩니다(전형적인 교육기관 테넌트 보안 정책).

## 3. 대체 실습 — 기존 테넌트 정보 읽기 전용 조회

포털 접근이 막혀 있었지만, **Azure CLI를 통한 Microsoft Graph 읽기 API는 정상 동작**했습니다. 이를 이용해 기존 테넌트의 구조를 조회하는 것으로 대체했습니다.

| 조회 항목 | 명령 | 결과 |
|---|---|---|
| 로그인 계정 정보 | `az ad signed-in-user show` | UPN `kyumni207@o.shinhan.ac.kr`, 개체 ID `247f****` (마스킹) |
| 테넌트 검증 도메인 목록 | `az rest --method get --url https://graph.microsoft.com/v1.0/domains` | `o.shinhan.ac.kr`(기본, 사용자 정의) / `shinhan365.onmicrosoft.com`(초기 도메인, isInitial: true) 2개 확인 |
| 전체 사용자 수 | `az rest ... /users/$count` (ConsistencyLevel: eventual) | 약 12,345명 |
| 내 디렉터리 역할 | `az rest ... /me/memberOf` | 결과 없음 → 관리자 역할 미보유 확인 (401의 원인과 일치) |
| 테넌트 내 디렉터리 역할 목록(정의) | `az rest ... /directoryRoles` | Global Reader 등 역할 정의 자체는 조회 가능(읽기 권한 있음) |

> ⚠️ 개인정보 보호: 조회된 전체 사용자 목록(학번 기반 UPN 다수 포함)은 **본 문서에 저장하지 않았습니다**. 인원수만 기록했습니다.

## 5. 해결 절차 (테넌트 생성을 반드시 해야 하는 경우)

1. 학교 조직 계정이 아닌 **개인 Microsoft 계정**(또는 무료/개인 Azure 체험 구독)으로 별도 로그인하여 시도 — 조직 정책의 영향을 받지 않음.
2. 학교 IT 관리자에게 "Microsoft Entra 관리자 센터 접근 권한" 또는 "테넌트 생성 권한" 요청.
3. 그래도 필요하다면, 실습 목적상 신규 테넌트 대신 **본 문서 3절의 읽기 전용 대체 실습**으로 개념(테넌트/도메인/사용자) 학습을 완료된 것으로 갈음.

## 6. 유지/정리 판단 기준

이번 실습에서는 **신규 테넌트가 생성되지 않았으므로 정리할 대상이 없습니다.**

(참고용 — 향후 개인 계정 등으로 테넌트 생성에 성공했을 경우의 유지/정리 기준)
- **유지**: 이후 차시 실습에서 재사용할 계획이 있거나, 하이브리드/멀티테넌트 개념 실습에 계속 필요한 경우.
- **정리**: 단발성 개념 확인용으로만 만들었고, 그 안에 구독·리소스·사용자를 추가하지 않은 경우 → 바로 삭제 권장(테넌트 삭제는 소속 리소스·라이선스가 없어야 가능하며 되돌릴 수 없음에 유의).
