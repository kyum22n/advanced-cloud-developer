### 주의 — 통합테스트 통과의 성격
통합테스트(6/6 Pass)는 **replicas=1로 임시 조정한 상태에서** 통과한 결과이며, replicas=2(정식 desired state)로 되돌린 뒤에는 SQLite 다중 레플리카 정합성 문제가 재발할 것으로 예상됨(재검증하지 않음 — 이미 원인이 명확하고 기존에 인지된 설계 한계이므로 반복 재현은 생략). **근본적으로 해결된 문제가 아니라, 데모 목적의 우회**임을 명시한다. 근본 해결책은 SQLite→PostgreSQL 전환 또는 공유 스토리지 도입(05_과정회고.md §3-1 "더 공부하면 좋을 주제 1"과 동일).

## 4단계 — prd 배포 시도 결과

**결론: 성공** (여러 차례 실패 발생 → 매번 사용자 확인 후 진행, 최종적으로 앱 구동·검증 완료. 롤백 실습만 사용자 결정으로 생략)

### 사전 발견 — myapp이 쓰지 않는 PostgreSQL·Redis·Storage
`env.prd.json`은 PostgreSQL(HA)·Redis·Storage를 실제 생성하도록 되어 있었으나, `myapp/package.json`에 `pg`/`redis`/Blob 클라이언트가 전혀 없어(SQLite+GitHub/Notion API만 사용) 이 셋은 myapp이 전혀 쓰지 않음을 확인. **사용자 승인 하에 생성 자체를 생략**(`env.prd.json`에 `skipPaasData: true` 추가, `20_config.ps1`·`10_prereq.ps1`을 조건부로 수정, `secretprovider.yaml`에서 미사용 시크릿 4종 제거). Key Vault·ACR·AKS만 실제 생성.

### 진행 순서와 발견·수정한 실제 버그
1. `az ad signed-in-user show` 정상 동작 확인(자기 자신 조회는 제한 없음). `az role assignment create --dry-run`은 이 az 버전에서 미지원이라 실제 호출로 대체 확인.
2. `10_prereq.ps1` → Provider 3종(KeyVault·Insights·Monitor) 미등록 발견 → 등록 후 18/18 Pass. (DBforPostgreSQL·Cache는 skipPaasData로 체크 자체를 생략하도록 스크립트 수정)
3. `20_config.ps1` 1차 실행 → **버그 발견**: `az keyvault list --query "[?starts_with(...)]"` 형태의 대괄호 필터 쿼리가 PowerShell→az.cmd 인자 전달 과정에서 깨짐(Bash에서는 정상, pwsh에서만 재현) → PowerShell 측 `Where-Object` 필터링으로 교체 수정.
4. 재실행 → **Forbidden 발견**: Key Vault가 `--enable-rbac-authorization true`인데 앱 관리 ID에만 읽기 역할(Secrets User)을 주고 **비밀을 쓰는 로그인 계정 자신에게는 쓰기 역할이 없어** `az keyvault secret set`이 `ForbiddenByRbac`로 실패. 더 심각한 건 **스크립트가 이 실패를 확인하지 않고 무조건 "[OK] 저장 완료"로 표시하던 버그**를 함께 발견 — 로그인 계정에 `Key Vault Secrets Officer` 역할 부여 + 실패 시 실제로 예외를 던지도록 수정.
5. 같은 재실행에서 **AKS 사용자 노드풀 생성 시 vCPU 쿼터 소진**(`left regional vcpu quota 0, requested quota 8`) 발견 → 1차 보고 후 사용자 확인. 사용자 지시대로 노드풀 크기를 D4s_v5×2(8vCPU)→D2s_v5×1(2vCPU)로 축소해 재시도했으나 **동일하게 실패**(쿼터 0은 그대로) → 사용자 지시(재실패 시 기록하고 다음 단계로)에 따라 **시스템 노드풀에 워크로드를 배포하는 방식으로 전환**(사용자 노드풀 추가 실패를 치명적 오류가 아닌 경고로 처리하도록 스크립트 수정).
6. `20_config.ps1` 최종 성공(exit 0) — RG·VNet·Log Analytics·App Insights·Key Vault(`kv-myapp-prd-lsrok`)·관리 ID·워크로드 ID 연합 자격 증명·AKS(시스템 3노드) 구성 완료. Key Vault 비밀 3종(github-token·notion-token·notion-parent-page-id) 실제 저장 확인.
7. `30_build.ps1` → ACR 클라우드 빌드 성공: `acrmyappprd.azurecr.io/myapp:prd-909b029`(불변 태그).
