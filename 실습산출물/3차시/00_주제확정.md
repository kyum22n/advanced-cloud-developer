# 0단계 · 준비 · 주제 · 데이터 소스 확정

작성일: 2026-08-28

## 1. 주제 한 문장 (누가·무엇을·왜)

**누가**: 자신이 만든(또는 기여한) GitHub 공개 레포를 이력서·포트폴리오에 정리해야 하는 개발자가
**무엇을**: GitHub 레포 URL 하나만 입력하면 레포의 구조(디렉터리 구성)·기술 스택·커밋 히스토리를 자동 분석해 "프로젝트 구조 + 기술 스택 + 프로젝트 설명" 리포트를 만들고, 사용자가 내용을 확인한 뒤 버튼 클릭으로 Notion 페이지(포트폴리오 아카이브)에 업로드하는 도구를
**왜**: 매번 레포를 직접 열어 폴더 구조·README·커밋 로그·언어 비율을 눈으로 훑고 손으로 포트폴리오 문서를 정리하는 반복 작업을 줄이기 위해 만든다.

### 지금의 수작업 흐름 (As-Is)
1. GitHub 레포 페이지 접속 → 파일 탐색기에서 폴더 구조를 눈으로 훑으며 파악
2. README를 읽고 프로젝트 목적·주요 기능 파악
3. Commits 탭에서 최근 커밋 메시지를 스크롤하며 개발 히스토리 파악
4. Insights → Languages 탭에서 언어 비율(기술 스택) 확인
5. 위 내용을 종합해 Notion 포트폴리오 페이지에 수동으로 새 항목 생성, 표·문단 작성
6. 레포 URL·확인 시각 등 출처 정보를 별도로 기록(생략되는 경우 많음)

레포 1건당 약 20~30분 소요(구조 파악 + README 정독 + 커밋 스캔 + Notion 정리 포함). 이직·이력서 갱신 시기마다 보유 레포 5~10건을 정리하면 회당 2~5시간 소요로 추정.

### 절감 시간 가설
- 자동화 시 레포 URL 입력부터 Notion 업로드까지 3~5분 이내 완료 목표
- 건당 **20~30분 → 5분 이내**, 시간 절감률 약 80% 이상 가설
- 부가 효과: 출처(레포 URL·커밋 SHA·수집 시각)를 매번 빠짐없이 기록 → 포트폴리오 신뢰도(언제 기준 분석인지 추적 가능) 향상

## 2. 데이터 소스 확정 — (b) 공개 데이터 수집

| 구분 | 내용 |
|---|---|
| 무엇을 | GitHub 공개 레포의 (1) 레포 메타데이터(이름·설명·기본 브랜치·라이선스·스타 수), (2) 디렉터리·파일 구조(트리, 포트폴리오 설명에 활용), (3) 최근 커밋 히스토리(작성자명·날짜·메시지, 이메일 등 개인식별 메타데이터는 리포트에 미노출), (4) 언어 통계(languages), (5) README |
| 어디서 | GitHub REST API 공개 엔드포인트 (`GET /repos/{owner}/{repo}`, `/git/trees/{sha}?recursive=1`, `/commits`, `/languages`, `/readme`) — 인증은 GitHub Personal Access Token(PAT, 공개 레포 read 권한)으로 Rate Limit 상향(비인증 60회/시간 → 인증 시 5,000회/시간) |
| 얼마나 자주 | 요청 시마다(On-demand) 재분석 — 정기 배치가 아니라 사용자가 레포 URL을 입력할 때마다 최신 상태로 수집 |
| 제약 | 공개(public) 레포만 대상. 비공개 레포·접근 권한 없는 레포는 API가 404를 반환하며 이를 "비공개이거나 존재하지 않음"으로 사용자에게 안내하고 수집 중단 |

보조 데이터: Notion Integration Token으로 Notion API(`POST /pages`)를 호출해 리포트를 업로드. 업로드 대상 워크스페이스·상위 페이지는 사전에 화면에 안내 후 진행.

## 3. 산출물 형태

**리포트 문서(Markdown) + 화면(입력/실행/미리보기/이력 대시보드) 둘 다**
- 화면: 레포 URL 입력 → 분석 실행 → 결과(프로젝트 구조·기술스택·요약) 미리보기 → Notion 업로드 버튼, 이전 분석 이력 목록
- 리포트: 분석 완료 시 생성되는 `.md` 리포트 파일(포트폴리오/이력서 첨부용, Notion에 그대로 업로드되는 원본)

## 4. 폴더 준비

- `실습산출물/3차시/myapp/` — 기존 존재(2차시 잔재 아님, 3차시 전용으로 유지) → 이번 앱 코드는 하위에 신규 구성
- `실습산출물/3차시/myapp/mockup/` — 기존 존재(0단계 환경점검 시 생성됨) → 2단계에서 사용
- `실습산출물/3차시/캡처/` — 기존 존재 → 2·4단계 캡처 저장에 재사용

## 5. 검증

| 검증 항목 | 결과 |
|---|---|
| 주제가 반복적·입력출력 분명·현재 수작업으로 하는 일인가 | O — 레포 URL(입력) → 리포트+Notion 페이지(출력), 현재 매번 수작업으로 반복 수행 중 |
| 민감 주제 여부 → (c) 가상 데이터로 전환 필요한가 | 해당 없음 — 공개 GitHub 레포 분석이며 개인 민감정보(HR 등)를 다루지 않음. 단, 커밋 메타데이터의 이메일 등은 리포트에 노출하지 않도록 3단계에서 마스킹 처리 |
