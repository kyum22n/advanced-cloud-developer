## 2. 핵심 파이프라인 전체 구현 여부

**판정: O** (엔드투엔드로 실제 동작함을 코드로 확인. 다만 "코드 변경 내용 분석"의 깊이에 대한 단서가 있어 아래에 명시)

| 파이프라인 단계 | 구현 여부 | 근거 |
|---|---|---|
| ① GitHub 레포 URL 입력 | O | [`myapp/public/index.html`](myapp/public/index.html) `#repoUrl` 입력창 + `#analyzeBtn` → `runAnalyze()`가 `POST /api/analyze` 호출 |
| ② 커밋 히스토리 분석 | O | [`myapp/src/github.js`](myapp/src/github.js) `analyzeRepo()` 내 `octokit.repos.listCommits(...)`(최대 30건, SHA 기준 중복 제거) |
| ③ "코드 변경 내용" 분석 | **△** | `github.js`에는 커밋 **메시지·날짜·SHA**와 레포 **디렉터리 구조**(Git Trees API)만 수집하며, 실제 파일별 추가/삭제 라인(diff/patch)을 가져오는 호출(`octokit.repos.getCommit` 등)은 없음(`grep "diff\|patch\|getCommit"` 결과 0건). 즉 "코드 변경 내용"은 커밋 메시지 요약 + 구조 스냅숏 수준이며, 실제 코드 diff 분석까지는 아님 |
| ④ 리포트 생성 | O | [`myapp/src/report.js`](myapp/src/report.js) `buildReportMarkdown()` — 개요·프로젝트 구조·기술스택·커밋 요약을 Markdown으로 생성 |
| ⑤ Notion 업로드 | O | 위 1번 항목과 동일 근거 |

**결론**: URL 입력 → 분석 → 리포트 생성 → Notion 업로드까지 코드 상으로 **끊김 없이 연결**되어 있고([`server.js`](myapp/server.js) `POST /api/analyze` → `POST /api/analyses/:id/notion-upload`), 실제 실행 로그도 `03_테스트결과.md`에 남아 있습니다. 다만 "코드 변경 내용 분석"이라는 표현이 커밋 diff 수준까지 기대한 것이라면 현재 구현은 그에 못 미칩니다(커밋 메시지+구조 스냅숏 수준).

## 4. `.env` 비밀값 노출 여부

**판정: O (노출 없음 확인)**

.env 파일 자체는 열람하지 않았고(`GITHUB_TOKEN=`·`NOTION_TOKEN=`·`NOTION_PARENT_PAGE_ID=` **키 이름 존재 여부만** 앞선 세션에서 이미 확인됨), 아래 대상 전체에서 실제 값이 그대로 옮겨 적힌 흔적을 검색했습니다.

| 검사 대상 | 방법 | 결과 |
|---|---|---|
| `실습산출물/3차시/*.md`(00~06 전체) | `ghp_`·`github_pat_`·`ntn_`·`secret_` 패턴 정규식 검색 | **0건** |
| `myapp/README.md` | 동일 | **0건** |
| `03_테스트시나리오.xlsx` | 바이너리 문자열(strings) 검색 | **0건** |
| git 커밋 이력(`git log --all -- "*.env"`) | `.env` 파일이 어느 커밋에도 포함된 적 없음 확인 | **0건**(추적 이력 없음) |
| `git status`(.env 파일) | 스테이징/추적 여부 확인 | 추적 안 됨 — `.gitignore`(`myapp/.gitignore:3`)에 `.env` 등록됨, `git check-ignore` 통과 |
| `myapp/node_modules/**/*.md` | 동일 패턴 검색 | `@octokit/auth-token/README.md`에 `ghp_PersonalAccessToken01245678900000000` 8건 매치 — **이는 octokit 라이브러리 자체의 공식 문서에 실린 예시용 더미 토큰**이며, 우리 프로젝트에서 작성하거나 실제 값을 옮긴 것이 아님(서드파티 의존성 문서, `node_modules`는 `.gitignore`로 제외됨) |
| 캡처 이미지(`캡처/*.png`) | 육안 재검토 | 모든 캡처는 웹 UI 화면(브라우저 렌더링 결과)만 담고 있고, 터미널·파일뷰어·`.env` 내용을 보여주는 캡처는 없음(각 캡처를 생성한 작업 기록 상 `.env`를 화면에 띄운 적이 없음) |

**결론**: 검토 대상 전체에서 실제 비밀값이 그대로 노출된 사례를 발견하지 못했습니다. `node_modules` 내 서드파티 문서의 더미 예시 토큰은 우리 프로젝트의 실제 값이 아니므로 노출로 간주하지 않았습니다.
