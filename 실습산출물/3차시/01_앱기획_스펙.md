# 1단계 · 앱 기획 · 스펙

작성일: 2026-08-28
> 참고: 이번 세션에서 context7 MCP가 연결 대기 상태라 실시간 조회가 되지 않아, 아래 라이브러리 후보는 공식 npm 등록정보·GitHub 저장소 기준의 일반 지식으로 비교했습니다. 3단계 구현 착수 전 context7이 연결되면 최신 버전·이슈 여부를 재확인합니다.

## 1. 핵심 사용자 스토리 (3개) + 성공지표(KPI)

| # | 사용자 스토리 | KPI |
|---|---|---|
| US1 | 개발자로서, 내 GitHub 공개 레포 URL을 입력하면 프로젝트 구조·기술스택·커밋 요약이 담긴 리포트를 자동으로 받고 싶다 | 레포 1건 분석 소요시간: 수작업 20~30분 → 5분 이내 |
| US2 | 개발자로서, 생성된 리포트를 별도 복사 작업 없이 Notion 포트폴리오 페이지에 바로 저장하고 싶다 | Notion 업로드까지 원클릭, 수동 복사·붙여넣기 0회 |
| US3 | 개발자로서, 과거에 정리한 레포 이력을 다시 찾아 이력서·포트폴리오 갱신 시 재사용하고 싶다 | 이력 목록에서 과거 분석 결과 재조회 100% 가능 |

## 2. MVP 범위 — 필수 / 나중

### 필수 (MVP)
- 레포 URL 입력 → 분석 실행 → 리포트 미리보기 → Notion 업로드
- 데이터 영속 저장(SQLite: 분석 이력, 리포트 원문)
- ~~엑셀/CSV 내보내기(분석 이력 목록)~~ — **미사용(범위 제외, 2026-08-28)**: 실제로 쓰이지 않아 코드·테스트에서 제거함. 이력은 화면(이력 목록)과 API(`GET /api/analyses`)로만 조회 가능
- 입력검증(URL 형식, owner/repo 파싱 실패 시 안내)
- 감사로그(누가·언제·무엇: 실행 시각·요청 URL·결과 성공/실패를 로그 테이블에 기록)
- 개인정보 처리: 커밋 작성자 이메일 등은 리포트·Notion에 미노출(마스킹)
- 로그인·권한(관리자/일반): 간이 구현 — 로컬 실습 환경 특성상 단일 사용자 기준의 간단한 역할 스위치(관리자=이력삭제 가능, 일반=조회·분석만)로 범위 축소. **구현 수준(2026-08-28 확정)**: URL 쿼리 파라미터(`?role=admin`)로 역할을 전환하며(비밀번호·세션 없음), `DELETE /api/analyses/:id`는 관리자가 아니면 실제로 403을 반환해 차단한다(단순 UI 숨김이 아니라 서버 측 접근 제어). 다만 URL 파라미터를 아는 사람은 누구나 관리자가 될 수 있어 **실제 인증은 아니며, 외부에 노출되지 않는 로컬/실습 환경 전용**이다

### 나중 (Post-MVP)
- 다중 사용자 인증(OAuth), 팀 단위 권한 분리
- 정기 배치 재분석(스케줄러)
- 레포 간 비교 리포트
- Slack 알림 연동

## 3. [데이터 규칙] 집계 기준

| 항목 | 규칙 |
|---|---|
| 분석 범위 | 레포의 **기본 브랜치(default_branch)** 기준, 최근 **커밋 30개** |
| 갱신 주기 | 배치 없음 — **요청(분석 실행 클릭) 시마다 재분석**, 매 실행 결과는 새 이력 레코드로 저장(덮어쓰지 않음) |
| 중복 제거 | 동일 커밋 SHA 중복 수신 시 SHA 기준 1건만 집계 |
| 결측 처리 | 커밋 0건(빈 레포) → "커밋 없음" 안내 후 메타데이터만으로 리포트 생성. languages API 결과 없음 → "언어 통계 없음" 표기 |
| 수집 대상(GitHub API) | `GET /repos/{owner}/{repo}`(메타데이터), `GET /repos/{owner}/{repo}/git/trees/{branch}?recursive=1`(디렉터리·파일 구조), `GET /repos/{owner}/{repo}/commits?per_page=30`(커밋), `GET /repos/{owner}/{repo}/languages`(언어 비율), `GET /repos/{owner}/{repo}/readme`(README, 있으면) |
| 실패 시 대체 | 404 → "비공개 레포이거나 존재하지 않는 레포입니다" 안내 후 중단 · 403(Rate Limit) → 남은 한도·초기화 시각 안내 후 중단 · 네트워크 오류 → 1회 재시도 후 실패 안내 |

## 4. 인수조건 (Given-When-Then, 정상 3 + 예외 3)

> **Notion 업로드 트리거 방식(재확인, 2026-08-28)**: 분석 완료 후 사용자가 리포트를 확인하고 **"Notion에 업로드" 버튼을 직접 클릭**하는 수동 방식으로 확정했다(자동 업로드 아님). 리포트 내용을 검토한 뒤 업로드 여부를 판단할 수 있고, 잘못 입력한 URL을 분석해도 Notion에는 올라가지 않으며, 이미 AC2·02_앱설계.md·실제 코드(`myapp/public/index.html`의 `#notionBtn`)가 이 방식으로 일치해 있어 추가 개발이 필요 없었다.

| AC-ID | 구분 | Given | When | Then |
|---|---|---|---|---|
| AC1 | 정상 | 유효한 공개 레포 URL이 주어졌을 때 | 분석 실행 버튼을 클릭하면 | 기술스택·커밋 요약이 포함된 리포트가 화면에 표시된다 |
| AC2 | 정상 | 리포트가 생성된 상태에서 | Notion 업로드 버튼을 클릭하면 | Notion에 새 페이지가 생성되고 업로드 성공 메시지와 페이지 링크가 표시된다 |
| AC3 | 정상 | 과거 분석 이력이 1건 이상 있을 때 | 이력 목록 화면에 접속하면 | 레포명·분석시각·상태가 목록으로 표시되고 상세를 다시 열람할 수 있다 |
| AC4 | 예외 | 존재하지 않거나 비공개인 레포 URL이 주어졌을 때 | 분석 실행 버튼을 클릭하면 | "비공개 레포이거나 존재하지 않는 레포입니다" 안내가 표시되고 리포트는 생성되지 않는다 |
| AC5 | 예외 | GitHub API Rate Limit이 소진된 상태에서 | 분석 실행 버튼을 클릭하면 | 한도 초과 안내와 재시도 가능 시각이 표시된다 |
| AC6 | 예외 | Notion Integration Token이 설정되지 않았거나 만료된 상태에서 | Notion 업로드 버튼을 클릭하면 | 401/403 기반 오류 메시지와 함께 ".env 설정을 확인하세요" 안내가 표시되고, 토큰 값 자체는 어디에도 노출되지 않는다 |
