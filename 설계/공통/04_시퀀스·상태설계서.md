## 1. APP-A 나만의 업무 앱

### 1-1. 기동 시퀀스 (프로브 계약의 근거)

```mermaid
sequenceDiagram
    participant K as Kubelet
    participant C as 컨테이너
    participant S as server.js
    participant D as db.js
    participant P as PostgreSQL

    C->>S: 프로세스 시작
    S->>D: createPool()
    S->>D: ensureSchema(pool)
    D->>P: CREATE TABLE IF NOT EXISTS ...
    alt 스키마 준비 성공
        P-->>D: OK
        D-->>S: resolve
        S->>S: dbReady = true
    else DB 미기동
        P--xD: 연결 실패
        D-->>S: reject
        S->>S: dbReady = false (기동은 계속)
    end
    S->>S: listen(8080)

    Note over K,S: startupProbe / livenessProbe
    K->>S: GET /healthz
    S-->>K: 200 ok

    Note over K,S: readinessProbe
    K->>S: GET /readyz
    alt dbReady = false
        S->>D: ensureSchema 재시도
        D->>P: 연결 시도
        P-->>D: OK
        S->>S: dbReady = true
        S-->>K: 200 ready
    else 여전히 실패
        S-->>K: 503 not-ready
    end
```

> 📌 **설계 의도** — DB 가 늦게 뜨더라도 **앱은 기동에 실패하지 않습니다.** `/readyz` 가 트래픽을 막아 주고, DB 가 준비되면 **자동으로 회복**됩니다. (AC-A-01 · AC-A-06)

### 1-2. 항목 등록 시퀀스 (FR-A-02·03·05)

```mermaid
sequenceDiagram
    actor U as 사용자
    participant UI as index.html
    participant S as server.js
    participant P as PostgreSQL

    U->>UI: 제목·금액 입력 후 [추가]
    UI->>S: POST /api/items {title, amount}
    S->>S: readBody() → JSON 파싱

    alt title 이 없거나 공백
        S-->>UI: 400 {error:"title 은 필수..."}
        UI-->>U: 알림 «입력값을 확인하세요»
    else amount 가 숫자 아님
        S-->>UI: 400 {error:"amount 는 숫자..."}
        UI-->>U: 알림
    else 검증 통과
        S->>P: INSERT INTO items(...) RETURNING *
        P-->>S: 생성된 행
        S->>P: INSERT INTO audit_log(actor, 'create', 'item:<id>')
        P-->>S: OK
        S-->>UI: 201 {id, title, amount, created_at}
        UI->>S: GET /api/items (목록 갱신)
        S-->>UI: 200 {count, items}
        UI-->>U: 표에 새 항목 표시
    end
```

### 1-3. 목록 조회 · 빈 상태 (FR-A-01·11)

```mermaid
sequenceDiagram
    participant UI as index.html
    participant S as server.js
    participant L as lib/summary.js
    participant P as PostgreSQL

    UI->>S: GET /api/items
    S->>P: SELECT ... ORDER BY id DESC LIMIT 200
    P-->>S: rows
    S->>L: dedupeById(rows)
    L-->>S: 중복 제거된 items
    S-->>UI: 200 {count, items}
    alt count = 0
        UI->>UI: #empty 표시 · #tbl 숨김
    else count > 0
        UI->>UI: #tbl 표시 · 행 렌더
    end
```

### 1-4. 주차 집계 시퀀스 (FR-A-04)

```mermaid
sequenceDiagram
    participant UI as 클라이언트
    participant S as server.js
    participant L as lib/summary.js
    participant P as PostgreSQL

    UI->>S: GET /api/summary
    S->>P: SELECT id, amount, created_at FROM items
    P-->>S: rows
    S->>L: summarizeByWeek(rows)
    loop 각 항목
        L->>L: isoWeek(createdAt) → "YYYY-Www"
        L->>L: 주차별 count += 1, amount += 금액
    end
    L->>L: 주차 오름차순 정렬
    L-->>S: WeekSummary[]
    S-->>UI: 200 {weeks:[...]}
```

> 🔎 **집계를 왜 DB 가 아니라 앱에서 하는가** — 주차 계산 규칙(ISO 8601·월요일 시작)을 **순수 함수로 두어 단위 테스트**하기 위함입니다. 데이터가 커지면 DB 집계(`date_trunc`)로 옮기고, 그때도 순수 함수는 **회귀 검증의 기준**으로 남습니다.

## 2. APP-B 웹 테트리스 게임

### 2-1. 게임 상태 머신 (FR-B-11·12)

```mermaid
stateDiagram-v2
    [*] --> READY
    READY --> PLAYING : 시작 키
    PLAYING --> PAUSED : P 키
    PAUSED --> PLAYING : P 키
    PLAYING --> GAMEOVER : 스폰 위치 충돌
    GAMEOVER --> READY : R 키(재시작)
    PAUSED --> READY : R 키(재시작)

    note right of PAUSED
        중력 틱 무시 (AC-B-08)
        입력 무시 (P·R 제외)
    end note
    note right of GAMEOVER
        보드 변경 없음 (AC-B-07)
        R 키만 허용
    end note
```

### 2-2. 중력 틱 시퀀스 (FR-B-04·07)

```mermaid
sequenceDiagram
    participant T as 타이머
    participant E as GameEngine
    participant B as Board
    participant SR as ScoreRule

    T->>E: tick()
    alt state ≠ PLAYING
        E-->>T: 무시 (AC-B-08)
    else PLAYING
        E->>B: isCollision(current, x, y+1)
        alt 충돌 없음
            B-->>E: false
            E->>E: current.y += 1
        else 충돌
            B-->>E: true
            E->>B: lock(current)
            E->>B: clearLines()
            B-->>E: 제거된 줄 수 n
            alt n > 0
                E->>SR: pointsFor(n, level)
                SR-->>E: 점수
                E->>E: score += 점수, linesCleared += n
                E->>SR: levelFor(linesCleared)
                SR-->>E: 새 레벨
                E->>SR: gravityInterval(level)
                SR-->>E: 새 간격
                E->>T: 타이머 간격 갱신
            end
            E->>E: current = next, next = 무작위 생성
            E->>B: isCollision(current, spawn)
            alt 스폰 충돌
                B-->>E: true
                E->>E: state = GAMEOVER (AC-B-06)
            end
        end
    end
```

### 2-3. 회전 + 월킥 시퀀스 (FR-B-03 · AC-B-03)

```mermaid
sequenceDiagram
    participant I as InputHandler
    participant E as GameEngine
    participant K as SrsKick
    participant B as Board

    I->>E: rotate(CW)
    E->>K: tryRotate(board, piece, CW)
    K->>K: rotated = piece.rotated(CW)
    K->>K: offsets = kickOffsets(type, from, to)
    loop 각 오프셋 (기본 위치 포함, 순서대로)
        K->>B: isCollision(rotated, x+dx, y+dy)
        alt 충돌 없음
            B-->>K: false
            K-->>E: 보정된 Piece 반환 → 회전 성공
        else 충돌
            B-->>K: true
        end
    end
    alt 모든 오프셋 실패
        K-->>E: null → 회전 취소 (보드 불변)
    end
```

### 2-4. 하드 드롭 시퀀스 (FR-B-06)

```mermaid
sequenceDiagram
    participant I as InputHandler
    participant E as GameEngine
    participant B as Board

    I->>E: hardDrop()
    loop 충돌할 때까지
        E->>B: isCollision(current, x, y+1)
        B-->>E: false
        E->>E: y += 1, dropDistance += 1
    end
    E->>B: lock(current)
    E->>B: clearLines()
    B-->>E: 제거된 줄 수
    E->>E: 점수 갱신 · 다음 블록 생성
    E-->>I: dropDistance
```

> 📌 **AC-B-05(테트리스 4줄)** 은 이 경로로 검증합니다 — 하드 드롭으로 4줄을 동시에 완성시켜 `800 × level` 점수를 확인합니다.
