| 메서드 | 경로 | 설명 | 상태코드 |
| --- | --- | --- | --- |
| POST | /api/analyze | 레포 URL 분석 실행 | 200/400/404/429 |
| GET | /api/analyses | 분석 이력 목록 조회 | 200 |
| GET | /api/analyses/:id | 분석 상세 + 리포트 조회 | 200/404 |
| POST | /api/analyses/:id/notion-upload | Notion 페이지 업로드(수동 트리거) | 200/401/403/502 |
| DELETE | /api/analyses/:id | 이력 삭제 (관리자 전용) | 200/403/404 |
•  Notion 업로드는 분석 완료 시 자동 실행되지 않고, 사용자가 결과를 확인한 뒤 버튼을 클릭해야 실행되는 수동 트리거입니다.
•  DELETE는 ?role=admin 이 아니면 서버가 실제로 403을 반환해 차단합니다 (단순 UI 숨김이 아닌 서버 측 접근 제어).

# 5. 배포

<!-- Slide number: 18 -->
5. 배포
5-1. 발생한 문제 (stg/prd 실배포 중)
| # | 문제 | 원인 |
| --- | --- | --- |
| 1 | stg 통합테스트 실패 — 방금 쓴 값을 못 찾음 | SQLite가 파드 로컬 파일인데 replicas=2라 LB가 요청을 다른 파드로 분산 |
| 2 | prd env.prd.json이 PostgreSQL·Redis·Storage를 생성하도록 설정 | myapp은 better-sqlite3+API만 사용 — 설계-구현 불일치 |
| 3 | Key Vault 비밀 저장 실패에도 스크립트가 '성공'으로 표시 | RBAC 쓰기 역할 누락 + 종료 코드 미확인 |
| 4 | AKS 사용자 노드풀 생성 시 vCPU 쿼터 소진 | 리전 쿼터가 stg+prd 시스템풀로 이미 소진(구독 하드 제약) |
| 5 | Argo CD CRD 설치 실패 (262144바이트 주석 한도) | prd가 client-side apply 사용 — stg에서 이미 고친 버그가 미반영 |
•  dev에서만 검증하고 stg·prd를 '설계상 되어 있다'로 넘겼다면 이 중 다수를 발견하지 못했을 것 — 실제 실행이 유일한 검증 수단

<!-- Slide number: 19 -->
5. 배포
5-2. 해결 방법
| # | 대응 | 결과 |
| --- | --- | --- |
| 1 | replicas를 1로 임시 조정→통합/E2E 통과 확인→2로 원복 후 selfHeal 검증 | 통합테스트 Pass(우회) · selfHeal 10초 내 자동 복구 실측 |
| 2 | skipPaasData: true 로 불필요한 PaaS 리소스 생성 자체를 생략 | 비용 절감, Key Vault·ACR·AKS만 생성 |
| 3 | 로그인 계정에 Key Vault Secrets Officer 부여 + 실패 시 예외 처리 | 비밀 3종 저장 확인 |
| 4 | 사용자 노드풀 없이 시스템 노드풀에 워크로드 배포로 전환 | 우회 성공(운영 모범사례는 쿼터 증설 후 원복 필요) |
| 5 | --server-side --force-conflicts 로 통일 | 해결 |
•  핵심 교훈: 근본 해결(공유 스토리지 전환 등)은 이번 범위 밖 — 우회는 임시 조치임을 설계 문서에 명시해 후속 작업으로 남김

# 6. 과정 회고

<!-- Slide number: 21 -->
6. 과정 회고
6. 과정 회고 — 현업 적용 & 다음 학습
반복 조사 업무 자동화 패턴 확산: 'URL 입력→자동 리포트→협업툴 업로드' — 건당 20~30분→5분(약 80% 절감), 출처(URL·시각) 자동 기록으로 감사 추적성 확보 (ROI 높음·난이도 낮음)
비밀 없는 접근 전면 적용: Key Vault + 워크로드 ID로 토큰 유출 가능성을 구조적으로 낮춤 (ROI 높음·난이도 중간)
배포 파이프라인 표준 템플릿화: 10~90단계 스크립트 + 80_verify 자동 검증을 팀 표준으로 (ROI 중간·난이도 중간)
•  다중 레플리카에서도 정합성이 유지되는 데이터 계층(PostgreSQL/PVC 공유 스토리지)으로 전환
•  GitHub/Notion 같은 서드파티 SaaS의 비밀 최소화 대안(OAuth App 등) 조사
•  GitOps selfHeal의 '의도된 긴급 변경' vs '실수'를 구분하는 운영 절차 학습
