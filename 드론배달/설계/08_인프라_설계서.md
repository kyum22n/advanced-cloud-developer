## 1. 설계 원칙

| # | 원칙 | 구체적 규칙 |
| --- | --- | --- |
| 1 | **선언적 · 재현 가능** | 포털 수동 변경 금지. 모든 변경은 코드 → PR → `plan` → `apply` |
| 2 | **환경은 변수로만 다르다** | 같은 모듈, 다른 `tfvars`. 환경별 별도 코드 금지 |
| 3 | **인프라와 워크로드를 분리** | Terraform 은 «그릇»만. 애플리케이션 배포는 별도 파이프라인 (OPS‑03) |
| 4 | **상태는 원격에 · 잠금 필수** | Azure Storage 백엔드 + blob 임대 잠금 |
| 5 | **비밀은 상태 파일에 남는다** | 상태 저장소를 **비밀처럼** 취급 (암호화·접근 제한·버전 관리) |
| 6 | **지역은 하드코딩하지 않는다** | 변수. 지역 장애 시 다른 지역에 재배포 가능 (OPS‑06) |
| 7 | **모든 리소스에 태그** | `env`, `system`, `owner`, `costCenter`, `managedBy=terraform` |
| 8 | **파괴적 변경은 사람이 승인** | `apply` 는 자동화하지 않음. `plan` 결과를 사람이 검토 |

## 2. 모듈 구조

```
구축/terraform/
├── modules/                          ← 재사용 단위 (환경을 모른다)
│   ├── naming/                       리소스 이름 생성 규칙
│   ├── network/                      VNet · 서브넷 · NSG · (허브 피어링)
│   ├── identity/                     사용자 할당 관리 ID · 역할 할당
│   ├── observability/                Log Analytics · App Insights
│   ├── registry/                     Container Registry
│   ├── keyvault/                     Key Vault (+ 프라이빗 엔드포인트)
│   ├── messaging/                    Service Bus · Event Hubs
│   ├── data/                         Redis · Cosmos(NoSQL) · Cosmos(Mongo) · Data Lake
│   ├── springapps/                   Azure Spring Apps + 6개 앱
│   ├── gateway/                      Application Gateway + WAF (+ Front Door)
│   └── private_endpoint/             프라이빗 엔드포인트 공통
│
├── envs/                             ← 환경별 조합 (모듈을 조립만)
│   ├── dev/{main.tf, variables.tf, terraform.tfvars, backend.tf, outputs.tf}
│   ├── stg/  (동일 구성)
│   └── prd/  (동일 구성)
│
└── shared/                           ← 환경 공통 (상태 백엔드 부트스트랩)
    └── bootstrap/                    상태 저장용 Storage · 컨테이너
```

> 🔑 **`envs/*/main.tf` 는 «조립만» 합니다.** 리소스를 직접 선언하지 않고 모듈만 호출합니다.
> 이렇게 해야 dev 와 prd 가 **구조적으로 동일**함이 코드로 증명됩니다.

## 3. 모듈별 명세

### 3.1 `naming`

```hcl
# 이름 규칙: {약어}-{system}-{env}-{region}[-{instance}]
# 예: rg-drone-prd-krc / asa-drone-prd-krc / cosmos-drone-prd-krc

output "prefix"        { value = "${var.system}-${var.env}-${var.region_short}" }
output "resource_group"{ value = "rg-${local.prefix}" }
output "spring_apps"   { value = "asa-${local.prefix}" }
output "vnet"          { value = "vnet-${local.prefix}" }
output "acr"           { value = replace("acr${var.system}${var.env}${var.region_short}", "-", "") }  # ACR 은 하이픈 불가
```

### 3.3 `identity`

앱마다 **사용자 할당 관리 ID** 를 하나씩 만들고, **리소스 범위**로만 역할을 부여합니다.

| 관리 ID | 부여 역할 | 범위 |
| --- | --- | --- |
| `id-drone-ingestion-{env}` | Azure Service Bus 데이터 보낸 사람 | 큐 `delivery-requests` |
| `id-drone-workflow-{env}` | Azure Service Bus 데이터 받는 사람 | 큐 `delivery-requests` |
| `id-drone-delivery-{env}` | Redis 데이터 소유자 · Event Hubs 데이터 보낸 사람/받는 사람 | 해당 리소스 |
| `id-drone-package-{env}` | Cosmos DB 기본 제공 데이터 기여자 | Mongo 데이터베이스 |
| `id-drone-dronesched-{env}` | Cosmos DB 기본 제공 데이터 기여자 · Event Hubs 데이터 보낸 사람 | 해당 |
| `id-drone-history-{env}` | Cosmos DB 데이터 기여자 · Event Hubs 데이터 받는 사람 · Storage Blob 데이터 기여자 | 해당 |
| (공통) | AcrPull | Container Registry |

> ⛔ **금지** — 구독 범위 역할 부여, `Contributor` 부여, 하나의 ID 를 여러 앱이 공유.

### 3.6 `springapps`

```hcl
module "spring_apps" {
  source = "../../modules/springapps"

  name                = module.naming.spring_apps
  sku                 = var.spring_apps_sku          # dev: S0 / prd: S0(Standard)
  vnet_injection      = var.env != "dev"
  app_subnet_id       = var.env != "dev" ? module.network.subnet_apps_id : null
  runtime_subnet_id   = var.env != "dev" ? module.network.subnet_runtime_id : null
  log_analytics_id    = module.observability.workspace_id
  app_insights_key    = module.observability.app_insights_connection_string

  apps = {
    ingestion       = { public = true,  instances_min = var.min_ingestion,  instances_max = 10, cpu = "1",   memory = "2Gi" }
    workflow        = { public = false, instances_min = var.min_workflow,   instances_max = 20, cpu = "1",   memory = "2Gi" }
    delivery        = { public = true,  instances_min = var.min_delivery,   instances_max = 12, cpu = "1",   memory = "2Gi" }
    package         = { public = false, instances_min = var.min_package,    instances_max =  8, cpu = "0.5", memory = "1Gi" }
    drone-scheduler = { public = false, instances_min = var.min_drone,      instances_max = 15, cpu = "1",   memory = "2Gi" }
    delivery-history= { public = true,  instances_min = var.min_history,    instances_max =  6, cpu = "1",   memory = "2Gi" }
  }
}
```

> **`instances_min` 을 변수로 둔 이유** — dev 는 1, stg 는 1~2, prd 는 2 입니다.
> 이 값만 `tfvars` 로 다르고 **구조는 동일**합니다 (원칙 2).

## 4. 상태 관리

### 4.1 백엔드 구성

```hcl
# envs/prd/backend.tf
terraform {
  required_version = ">= 1.9.0"
  backend "azurerm" {
    resource_group_name  = "rg-drone-tfstate"
    storage_account_name = "stdronetfstate"
    container_name       = "tfstate"
    key                  = "prd.terraform.tfstate"
    use_azuread_auth     = true          # ★ 스토리지 키 대신 Entra 인증
  }
}
```

| 항목 | 설정 | 이유 |
| --- | --- | --- |
| 상태 파일 분리 | 환경별 다른 `key` | 한 환경의 실수가 다른 환경에 영향 없음 |
| 잠금 | Blob 임대 (자동) | 동시 `apply` 방지 |
| 버전 관리 | ✅ Blob 버전 관리 | 상태 손상 시 복구 |
| 접근 | **Entra 인증 + RBAC** | 스토리지 키 사용 금지 |
| 암호화 | 기본 + 인프라 암호화 | 상태에 비밀이 남을 수 있음 |
| 삭제 방지 | 리소스 잠금 (`CanNotDelete`) | 상태 소실 = 인프라 통제 상실 |

> ⚠️ **상태 파일에는 비밀이 평문으로 남을 수 있습니다.** (연결 문자열·키 등)
> 그래서 이 설계는 **가능한 모든 곳에서 워크로드 ID** 를 쓰고, 상태 저장소를 **비밀처럼** 보호합니다.

## 5. 프로바이더 · 버전 고정

```hcl
terraform {
  required_version = ">= 1.9.0, < 2.0.0"
  required_providers {
    azurerm = { source = "hashicorp/azurerm", version = "~> 4.0" }
    azuread = { source = "hashicorp/azuread", version = "~> 3.0" }
    random  = { source = "hashicorp/random",  version = "~> 3.6" }
  }
}

provider "azurerm" {
  features {
    key_vault {
      purge_soft_delete_on_destroy    = false   # ★ 실수로 영구 삭제되지 않게
      recover_soft_deleted_key_vaults = true
    }
    resource_group {
      prevent_deletion_if_contains_resources = true   # ★ 안전장치
    }
  }
}
```

| 규칙 | 이유 |
| --- | --- |
| **버전 범위 고정** (`~>`) | 프로바이더 주 버전 변경이 예고 없이 들어오면 `plan` 이 폭발 |
| `.terraform.lock.hcl` **커밋** | 팀·CI 가 정확히 같은 프로바이더 사용 |
| `prevent_deletion_if_contains_resources` | 리소스 그룹 통째 삭제 사고 방지 |

## 6. 실행 절차 (사람이 수행)

> ⛔ **본 과제에서는 실제로 실행하지 않습니다.** 아래는 산출물로서의 절차 정의입니다.

```
 ① 전제 확인      구축/scripts/10_prereq.ps1      구독·권한·CLI 버전·할당량
 ② 초기화        terraform init
 ③ 형식·검증      terraform fmt -check / validate  · tflint · checkov
 ④ 계획          terraform plan -out=tfplan       ← ★ 사람이 반드시 검토
 ⑤ 승인          (사람) 변경 목록 확인 · 파괴 항목 확인
 ⑥ 적용          terraform apply tfplan
 ⑦ 검증          구축/scripts/80_verify.ps1       리소스·역할·네트워크 확인
 ⑧ 출력          terraform output -json > env.{env}.json
 ⑨ (필요 시) 정리 구축/scripts/90_cleanup.ps1      ← 'yes' 확인 필수
```

### 6.1 `plan` 검토 시 확인할 것

| 확인 항목 | 위험 신호 |
| --- | --- |
| `destroy` 대상이 있는가 | 데이터 저장소가 destroy 목록에 있으면 **즉시 중단** |
| `~` (변경) 이 재생성을 유발하는가 | `forces replacement` 표시 확인 |
| 예상하지 않은 리소스가 있는가 | 드리프트(포털 수동 변경) 흔적 |
| 비밀이 평문으로 보이는가 | `sensitive = true` 누락 |
| 태그가 빠진 리소스가 있는가 | 비용 추적 불가 |

## 8. 환경 승격 규칙

```
   dev ──────▶ stg ──────▶ prd
        │           │
        │           └─ 조건: stg 검증(80_verify) fail = 0 기록이 있어야 함
        └─ 조건: dev 검증 통과 · plan 에 파괴 항목 없음
```

| 환경 | 승격 조건 | 승인자 |
| --- | --- | --- |
| dev | 없음 (자유) | 개발자 |
| stg | dev 검증 통과 | 개발자 |
| **prd** | **stg 검증 결과 파일(`stg_verify_*.json`) 의 `fail = 0`** | **운영 담당자 별도 승인** |

## 9. 비용 가시성

| 조치 | 구현 |
| --- | --- |
| 모든 리소스에 필수 태그 | `default_tags` 를 프로바이더 수준에 정의 + 검증 스크립트 |
| 예산 경고 | Terraform 으로 Consumption Budget 생성 (dev/stg/prd 각각) |
| 비용 추정 | `terraform plan` 후 `infracost`(선택) |

```hcl
locals {
  common_tags = {
    system     = "drone-delivery"
    env        = var.env
    owner      = var.owner
    costCenter = var.cost_center
    managedBy  = "terraform"
    createdAt  = var.deployed_at      # ← 파이프라인이 주입 (timestamp() 는 매번 변경되어 드리프트 유발)
  }
}
```

> ⚠️ **`timestamp()` 함수를 태그에 쓰지 마세요.** `plan` 할 때마다 값이 바뀌어 **모든 리소스가 변경 대상**이 됩니다.
> 배포 시각은 파이프라인이 변수로 주입합니다.

## 10. 드리프트 관리

| 상황 | 조치 |
| --- | --- |
| 포털에서 누가 수동 변경 | `terraform plan` 이 차이를 표시 → **코드를 고쳐 반영** (수동 변경을 되돌리는 게 아니라) |
| Azure 가 자동으로 추가한 속성 | `lifecycle { ignore_changes = [...] }` 로 명시적 무시 |
| 정기 드리프트 점검 | 주 1회 `plan` 을 CI 에서 실행하고 차이가 있으면 알림 |
