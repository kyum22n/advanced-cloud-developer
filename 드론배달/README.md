# 드론 배달 — DDD·SDD 기반 Azure 마이크로서비스

> **시나리오** — 가상의 회사 **Fabrikam, Inc.** 는 드론 항공기를 운영합니다. 기업이 서비스에 등록하면
> 사용자는 배달할 상품을 드론이 픽업하도록 요청할 수 있습니다. 고객이 픽업을 예약하면 백엔드 시스템이
> **드론을 할당하고 예상 배달 시간(ETA)** 을 사용자에게 알립니다. 고객은 배달이 진행되는 동안
> **드론의 위치를 추적**하고 지속적으로 갱신되는 ETA를 확인할 수 있습니다.
>
> 출처 — Microsoft Learn 「도메인 분석을 사용하여 마이크로 서비스 모델링」 / 「고급 AKS 마이크로 서비스 아키텍처」
> 및 첨부 `강의자료-최종/azure-architecture.pdf`(Azure 아키텍처 센터 전체본, 4,953p).

## 2. 방법론 — DDD 와 SDD 를 어디에 쓰는가

두 방법론은 **경쟁 관계가 아니라 층이 다릅니다.**

| | **DDD** (Domain‑Driven Design) | **SDD** (Spec‑Driven Development) |
| --- | --- | --- |
| 다루는 것 | *무엇을 모델링할 것인가* | *어떻게 만들어 낼 것인가* |
| 산출물 | 유비쿼터스 언어 · 컨텍스트 맵 · 애그리거트 | `spec.md` · `plan.md` · `tasks.md` |
| 이 과정에서의 역할 | **서비스 경계를 정한다** | **AI 협업으로 그 경계를 코드로 만든다** |
| 실패 시 증상 | 분산된 단일체(distributed monolith) | 그럴듯하지만 요구사항과 다른 코드 |

```
   ┌──────────────── DDD ────────────────┐   ┌────────── SDD ──────────┐
   도메인 분석 → 컨텍스트 → 애그리거트 →→→ spec.md → plan.md → tasks.md → 코드
      (분석/02)   (분석/02)   (분석/04)      (설계/11)              (개발/·구축/)
                                  │                                    │
                                  └────────── 추적성 매트릭스 ─────────┘
                                              (설계/12)
```

## 4. 실행 원칙 (이 폴더의 안전 수칙)

- ⛔ **이 폴더의 어떤 스크립트도 자동으로 실행되지 않습니다.** 모든 `terraform apply` · `az` 명령은
  사람이 직접, 확인 프롬프트에 응답한 뒤에만 수행됩니다. 문서와 코드는 **산출물**입니다.
- ⛔ 비밀값(연결 문자열·키·비밀번호)은 코드·Git·이미지에 **평문으로 두지 않습니다.**
  Azure 리소스 접근은 **워크로드 ID(암호 없는 연결)** 를 1순위로 합니다 → [`설계/09`](설계/09_보안_아이덴티티_설계서.md)
- ⛔ 방화벽 `0.0.0.0/0` 금지 · 컨테이너 `latest` 태그 금지 · 구독 범위 역할 부여 금지.
- ⛔ 실제 개인정보·주소·연락처는 사용하지 않습니다. 모든 예제 데이터는 가상입니다.
- ✅ `prd` 는 `stg` 검증 통과 기록이 있어야 진행합니다.
