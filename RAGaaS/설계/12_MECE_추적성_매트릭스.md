## 5. ME 검증 — 중복 책임 점검

| 잠재 중복 | 확인 | 판정 |
| --- | --- | :---: |
| 청킹이 로컬과 Azure 양쪽에? | 로컬 = 파라미터 «실험», Azure = 그 파라미터로 «실행». 목적이 다름 | ✅ 분리 |
| 재순위가 RRF 와 중복? | RRF = «융합», 재순위 = «재정렬». 순서가 다름 | ✅ 분리 |
| 권위 가중과 재순위가 중복? | 재순위 = 질의‑문서 관련성, 가중 = 문서 «유형» 신뢰도. 축이 다름 | ✅ 분리 |
| 보안이 필터와 프롬프트 양쪽에? | **필터가 유일한 방어.** 프롬프트는 보조 | ✅ 단일 |
| 상태 필터와 권위 가중이 중복? | 필터 = 결정적 배제, 가중 = 점수 조정. 강도가 다름 | ✅ 분리 |
| 검색 평가와 생성 평가가 중복? | 검색 = 근거 찾기, 생성 = 근거 사용. 단계가 다름 | ✅ 분리 |
| 에이전트와 하이브리드가 중복? | 에이전트가 «내부적으로» 하이브리드를 쓴다. 포함 관계 | ✅ 계층 |

## 6. ★ 하지 못한 것 (숨기지 않고 나열)

### 6.1 실행하지 않은 것

| 항목 | 이유 | 필요한 것 |
| --- | --- | --- |
| **Azure 실제 배포** | 구독·과금은 별도 판단 (CON‑07) | 구독 · 예산 승인 |
| **Azure OpenAI 임베딩** | 과금 | 자격 증명 |
| **생성 단계 검증** | LLM 호출 필요 | 채팅 배포 |
| **플레이그라운드 시연** | 인덱스 배포 선행 필요 | ⑤~⑧ 단계 |
| **성능 측정** (p95) | 배포 선행 | 부하 도구 |

### 6.2 측정하지 않은 것

| 항목 | 영향 | 다음 단계 |
| --- | --- | --- |
| 청크 크기 A/B (500/800/1200) | 현재 값이 최적인지 모름 | 3회 재색인 후 비교 |
| 임베딩 모델 A/B (large/small) | 비용‑품질 균형 미확인 | 한국어 A/B |
| 차원 A/B (1536/3072) | 축소 손실 미확인 | 한국어 A/B |
| 근거 개수 A/B (3/5/10) | 5건이 최적인지 모름 | 생성 평가 필요 |
| 분석기 A/B (ko.microsoft/ko.lucene) | 어느 쪽이 나은지 모름 | 배포 후 비교 |
| **라우팅 판별 정확도** | «라우팅이 이득»을 단정 못 함 | 분류 정확도 측정 |
| 근거 점수 임계값 | 1.8 은 «출발점» | 점수 분포 분석 |

### 6.3 적용하지 않은 것

| 항목 | 권장도 | 이유 |
| --- | --- | --- |
| **Prompt Shields** | **필수** | 운영 전 반드시 |
| **Groundedness Detection** | **필수** | 환각 감지 |
| Azure AI Language PII | 실 데이터 시 필수 | 가상 데이터라 불필요 |
| Document Intelligence | 실 PDF 시 필수 | 텍스트 코퍼스라 불필요 |
| 동의어 맵 | 권장 | 사전은 [분석/02 §8](../분석/02_도메인_지식체계_분석.md) 에 준비됨 |
| 질의·응답 로깅 | 권장 | 구현 안 함 |
| 피드백 수집 | 권장 | 구현 안 함 |

### 6.4 대체물로 검증한 것 — 한계를 명시

| 실제 | 대체 | 한계 |
| --- | --- | --- |
| Azure OpenAI 임베딩 | **로컬 LSA** | 외부 지식 없음. 동의어 유형이 실제보다 낮게 나올 가능성 |
| Azure 시맨틱 랭커 | **IDF 가중 근사** | 학습된 교차 인코더가 아님. 버전충돌에서 오히려 하락한 사례 |
| LLM 쿼리 분해 | **규칙 기반** | 표현이 예상 밖이면 분해 못 함 |

> ⚠️ **이 대체물로 잰 수치는 «전략 간 상대 비교»에 쓰고, «운영 품질의 절대 예측»에 쓰지 않습니다.**

```
        · Prompt Shields · Groundedness Detection 적용

```
