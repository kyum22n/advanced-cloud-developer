# 인사·총무 Hybrid RAGaaS

> 사내 인사·총무 문의를 **현행 규정에 근거해서, 출처와 함께** 답하는 RAG 서비스.
> 없는 답은 **없다고 말하는 것**이 이 시스템의 첫 번째 요구사항입니다.

| 항목 | 값 |
| --- | ---: |
| 가상 문서 | **11,021건** (2,871,751자) |
| 청크 | **12,863건** (상한 초과 0건) |
| 벡터 | 12,863 × 256 (로컬 LSA — 오프라인 검증용) |
| 심어 둔 함정 | 34건 |
| 평가 세트 | 38건 (7유형) |
| 비교한 검색 전략 | 7종 |
| 문서 | 분석 7편 · 설계 12편 · README 3편 · 실습 프롬프트 1편 |

## 3. 측정 결과 (K=5 · 38건 · 로컬 LSA)

| 전략 | Recall | Prec | MRR | nDCG | 보안위반 | 구버전우선 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| keyword | 0.701 | 0.379 | 0.645 | 0.557 | **0** | **0** |
| vector | 0.575 | 0.303 | 0.515 | 0.393 | **0** | **0** |
| hybrid | 0.598 | 0.331 | 0.527 | 0.436 | **0** | **0** |
| semantic | 0.609 | 0.283 | 0.605 | 0.451 | **0** | **0** |
| **boosted** | **0.793** | 0.352 | **0.801** | **0.667** | **0** | **0** |
| agentic | 0.540 | 0.276 | 0.543 | 0.403 | **0** | **0** |
| agentic+boost | 0.713 | 0.317 | 0.707 | 0.574 | **0** | **0** |

유형별로는 **keyword 가 숫자 정밀도(1.000)에서 hybrid(0.400)를 이기고**,
**agentic+boost 가 다중 홉(0.556)에서 가장 높습니다.** 자세한 표는 [테스트/README.md §4](테스트/README.md).

### 이 프로젝트가 실측으로 확인한 것

```
   ① 가장 큰 개선은 «모델»이 아니라 «도메인 지식»이었다
        문서 유형 권위 가중 하나로 Recall +30 % · MRR +32 % · nDCG +48 %
        임베딩 모델이나 청크 크기 조정보다 효과가 컸다

   ② 「하이브리드가 항상 낫다」는 거짓이다
        숫자 정밀도에서 keyword(1.000) > hybrid(0.400)
        RRF 는 «두 방식이 비슷하게 좋을 때» 이득이다

   ③ 단일 전략이 모든 유형을 이기지 못한다  → 질의 라우팅이 필요하다

   ④ 잘못된 지표가 «없는 문제»를 만들었다
        버전충돌 Recall 0.000 → 확인해 보니 구버전은 58위, 현행은 15위였다
        구버전이 이긴 적이 없었다. 진짜 문제는 FAQ 노이즈였다

   ⑤ 보안은 «검색 필터»이지 «프롬프트»가 아니다
        검색 단계 배제는 결정적, 프롬프트 지시는 확률적이다
```

## 5. 빠른 실행

```bash
cd RAGaaS
python 개발/generator/korean.py                                  # 조사 13/13
python 개발/generator/generate_corpus.py --seed 20260829         # 11,021건
python 개발/pipeline/chunker.py --target 800 --max 1200          # 12,863청크
python 개발/pipeline/embed.py --estimate-only                    # ★ 규모 먼저 확인
python 개발/pipeline/embed.py --backend local-lsa --dim 256
python 테스트/goldenset/build_goldenset.py                       # 38건
python 테스트/eval/eval_retrieval.py --k 5                       # 7전략 비교
python 개발/config/build_azure_config.py --env dev
python 개발/config/deploy_index.py --env dev --dry-run           # 배포하지 않음
python 테스트/verify_artifacts.py                                # 산출물 무결성 검증
```

의존성은 **numpy 뿐**입니다. Azure 호출 없이 전 과정을 검증할 수 있습니다.

## 6. ⚠️ 무엇을 실행했고 무엇을 하지 않았는가

| 실행함 | 결과 |
| --- | --- |
| 코퍼스 생성 · 조사 검증 | 11,021건 · 미해결 조사 0건 |
| 청킹 | 12,863청크 · 상한 초과 0건 |
| 로컬 LSA 임베딩 | 12,863 × 256 |
| 하이브리드 · 에이전트 검색 | 동작 확인 |
| 검색 품질 평가 | 7전략 × 38건 |
| Azure 구성 JSON 생성 | 8개 파일 (전부 파싱 확인) |
| 배포 계획 확인 | `--dry-run` — **아무것도 배포하지 않음** |

| 실행하지 않음 | 이유 |
| --- | --- |
| Azure 실제 배포 | 구독·과금·정리 책임은 별도 판단 |
| Azure OpenAI 임베딩 호출 | 과금 |
| 채팅 모델 호출 (**생성 단계 평가**) | 과금 · 자격 증명 |
| 플레이그라운드 시연 | 배포 선행 필요 |

> **가장 시급한 미완은 «생성 평가»입니다.** 검색이 완벽해도 LLM 이 근거를 무시하면
> 소용없습니다. 환각·거절 정확도는 아직 측정되지 않았습니다.

### 대체물로 검증한 것

| 실제 | 이 프로젝트 | 한계 |
| --- | --- | --- |
| Azure OpenAI 임베딩 | 로컬 LSA (TF‑IDF + SVD) | 외부 지식 없음. «법카 ↔ 법인카드»를 모른다 |
| Azure 시맨틱 랭커 | IDF 가중 근사 | 학습된 교차 인코더가 아니다 |
| LLM 쿼리 분해 | 규칙 기반 | 표현이 예상 밖이면 분해 못 한다 |

> 이 수치는 **«전략 간 상대 비교»** 에 쓰고, **«운영 품질의 절대 예측»** 에 쓰지 않습니다.

## 7. 안전 원칙

| 원칙 | 적용 |
| --- | --- |
| 실제 인사 정보·개인정보 금지 | 회사·부서·규정 전부 가상. 이름·사번·연락처 없음. 도메인은 `*.example` (RFC 2606) |
| 비밀을 코드·Git 에 두지 않음 | `.env.example` 에 **주소만**. `API_KEY` 항목은 «절대 쓰지 않는다»로 주석 처리 |
| 인증은 관리 ID | `DefaultAzureCredential`. API 키 경로를 코드에 두지 않음 |
| 접근 제어는 검색 필터 | `security_level` 필터를 항상 적용. 프롬프트 지시에 의존하지 않음 |
| 파괴적·과금 작업은 확인 필수 | `deploy_index.py` 는 정확히 `yes` 입력 필요. `--force` 플래그 없음 |
| 비용은 쓰기 «전에» 확인 | `embed.py --estimate-only`. 단가는 임의로 채우지 않고 «확인 필요»로 남김 |
