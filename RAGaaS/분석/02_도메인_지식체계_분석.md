# 02. 도메인 지식 체계 분석 — 인사·총무 택소노미

> **목적** — 문서를 «어떤 축으로 분류할 것인가»를 정합니다.
> 이 분류가 그대로 **인덱스의 필터 필드**가 되므로, 여기서 빠뜨린 축은 나중에 필터할 수 없습니다.
> 앞: [01_요구사항_분석.md](01_요구사항_분석.md) · 다음: [03_질의_유형_분석.md](03_질의_유형_분석.md)

---

## 1. 왜 «분류»부터 하는가

RAG 를 «문서를 벡터로 만들어 넣으면 끝»이라고 보면 다음이 불가능해집니다.

| 못 하게 되는 것 | 필요한 축 |
| --- | --- |
| "인사 관련만 찾아줘" | 대분류 |
| "폐지된 규정 말고 현행만" | 상태 |
| "규정 말고 실무 절차서에서" | 문서 유형 |
| "일반 직원에게 제한 문서를 숨겨야" | **보안 등급** |
| "작년 공지 말고 올해 것" | 시행일·만료일 |
| "누구한테 물어봐야 하지" | 소관 부서 |

> 🔑 벡터 검색은 «비슷한 것»을 찾습니다. **«맞는 것»을 찾으려면 메타데이터가 필요합니다.**

---

## 2. 분류 축 (5축)

```
   ① 주제 축      대분류 → 중분류 → 세부주제      "무엇에 관한 문서인가"
   ② 형식 축      문서 유형                       "어떤 종류의 문서인가"
   ③ 수명 축      상태 · 버전 · 시행일 · 만료일    "지금 유효한가"
   ④ 접근 축      보안등급 · 대상                  "누가 볼 수 있는가"
   ⑤ 소유 축      소관 부서                        "누가 관리하는가"
```

각 축은 **서로 독립**입니다(ME). 예: «인사 / FAQ / 현행 / 공개 / 인사팀»은 모든 축에 값이 하나씩.

## 3. ① 주제 축 — 3단계 택소노미

### 3.1 대분류 (2)

| 대분류 | 정의 | 문서 수(생성 결과) |
| --- | --- | ---: |
| **인사** | 사람의 채용·평가·보상·근로조건에 관한 것 | 5,636 |
| **총무** | 자산·시설·비용·계약 등 회사 운영에 관한 것 | 5,385 |

> 경계가 애매한 것: **복리후생**. 사람에 관한 것이지만 «예산·시설 운영»이 실무의 중심이라 총무로 두었습니다.
> ⚠️ 이런 판단은 조직마다 다릅니다. **실제 조직의 소관 부서**를 기준으로 정하는 것이 안전합니다.

### 3.2 중분류 (24)

| 인사 (12) | 총무 (12) |
| --- | --- |
| 채용 · 인사이동 · 평가 · 승진 | 비품 · 자산 · 사무공간 · 출입보안 |
| 교육 · 근태 · 휴가 · 휴직 | 차량 · 출장 · 경비 · 계약 |
| 급여 · 보험 · 퇴직 · 노무 | 구매 · 문서 · 복리후생 · 행사 |

### 3.3 세부주제 (145)

중분류마다 4~6개. 예:

```
인사 > 휴가 > 연차휴가 · 경조휴가 · 병가 · 공가 · 포상휴가 · 무급휴직
총무 > 출장 > 국내출장 · 해외출장 · 출장신청 · 출장비정산 · 숙박기준
```

> 💡 **세부주제가 «검색 필터»보다 «분석 축»으로 더 유용합니다.**
> 사용자는 "휴가 관련"까지는 말하지만 "연차휴가 카테고리로 필터"라고 말하지 않습니다.
> 대신 «어느 주제 질의가 많은가»를 집계할 때 이 축이 쓰입니다.

## 4. ② 형식 축 — 문서 유형 (9)

**이 축이 청킹 전략과 검색 순위를 좌우합니다.** 가장 중요한 축입니다.

| 유형 | 건수 | 평균 길이 | 성격 | 청킹 | 권위 |
| --- | ---: | ---: | --- | --- | ---: |
| **규정** | 527 | 200자 | 조문. 법적 근거 | 자르지 않음 (조가 이미 단위) | 2.0 |
| **규정전문** | 20 | ~8,000자 | 규정 전체본 | **반드시 분할** | 1.8 |
| **안내서** | 905 | 473자 | 기준표·한도표 | 자르지 않음 | 1.7 |
| **지침** | 149 | 364자 | 실무 절차 | 자르지 않음 | 1.5 |
| **매뉴얼** | 220 | ~2,600자 | 종합 운영서 | **절 단위 분할** | 1.4 |
| **서식안내** | 400 | 272자 | 양식 사용법 | 자르지 않음 | 1.2 |
| **공지** | 1,200 | 197자 | 시한 있는 안내 | 자르지 않음 | 1.1 |
| **FAQ** | 3,600 | 140자 | 짧은 질문·답 | 자르지 않음 | 1.0 |
| **문의이력** | 4,000 | 265자 | 개별 사례 | 자르지 않음 | 0.8 |

### 4.1 «권위» 열이 왜 필요한가 — 측정된 근거

이 코퍼스는 **FAQ + 문의이력이 7,600건(69 %)** 으로 규정·안내서(1,452건)를 수적으로 압도합니다.
그래서 이런 일이 실제로 일어났습니다.

```
   질의: "연차휴가 한도가 며칠인가요?"

   재순위 결과 (권위 가중 없음)
     1위  연차휴가 한도가 어떻게 되나요?              (FAQ)
     2위  수습 기간인데 연차휴가 한도가 어떻게 되나요?  (FAQ)
     3위  해외근무 중인데 연차휴가 한도가…            (FAQ)
     …
    15위  연차휴가 운영기준 (현행)                    (규정) ← 정작 정답
```

FAQ 변형 수십 개가 상위를 채우고 **권위 있는 규정이 15위로 밀립니다.**
사용자는 FAQ 의 요약된 수치를 보게 되고, 그것이 규정과 다르면 잘못 안내됩니다.

**문서 유형 가중을 적용한 결과** (평가 세트 38건 기준)

| 지표 | 가중 없음 | 가중 적용 | 변화 |
| --- | ---: | ---: | --- |
| Recall@5 | 0.609 | **0.793** | +30 % |
| MRR | 0.605 | **0.801** | +32 % |
| nDCG@5 | 0.451 | **0.667** | +48 % |
| 버전충돌 Recall@5 | 0.000 | **1.000** | — |

> 🔑 **이것이 이 프로젝트에서 가장 큰 단일 개선이었습니다.**
> 임베딩 모델을 바꾸거나 청크 크기를 조정하는 것보다 효과가 컸습니다.
> 근거: [테스트/eval/eval_result_k5.json](../테스트/eval/)

## 5. ③ 수명 축 — 상태 · 버전 · 기간

| 필드 | 값 | 용도 |
| --- | --- | --- |
| `status` | 현행 / 개정예정 / 폐지 | **가장 중요한 필터** |
| `version` | 1.0, 2.1 … | 같은 문서군의 세대 |
| `effective_date` | 시행일 | 최신성 정렬 |
| `expiry_date` | 만료일 (공지) | 지난 공지 배제 |

생성 결과: 현행 9,702 · 폐지 1,089 · 개정예정 230

### 5.1 «삭제하지 않고 상태로 두는» 이유

```
   ❌ 폐지 문서를 지운다
      · "작년에는 어땠나요?" 에 답할 수 없다
      · 개정 이력을 설명할 수 없다
      · 감사·분쟁 시 근거가 사라진다

   ✅ 상태로 표시하고 검색에서 제외한다
      · 기본 검색에서는 안 보인다 (status eq '현행' 필터)
      · 이력 질의에서는 필터를 풀어 조회한다
      · 답변에서 "2025년까지는 10일이었으나 2026년부터 20일" 이라고 설명할 수 있다
```

## 6. ④ 접근 축 — 보안 등급 · 대상

| 등급 | 건수 | 예시 | 접근 |
| --- | ---: | --- | --- |
| **공개** | 3,215 | 서식 안내, 일반 FAQ | 전원 |
| **사내** | 7,466 | 규정, 지침, 매뉴얼 | 임직원 |
| **제한** | 340 | 징계 양정, 급여 테이블, 평가등급 배분 | 인사담당자·관리자 |

### 6.1 ★ 접근 제어는 «검색 단계»에서 해야 한다

```
   ❌ LLM 프롬프트로 막기
      "제한 등급 문서는 사용자에게 보여 주지 마세요"
      → 프롬프트 주입 한 번이면 뚫린다
      → 이미 컨텍스트에 들어간 내용은 «본 것»이다

   ✅ 검색 필터로 배제하기
      filter: security_level ne '제한'
      → 애초에 후보에 들어오지 않는다
      → LLM 이 볼 수 없으므로 유출할 수도 없다
```

측정 결과: 전 전략에서 **제한 문서 노출 0건** ([테스트/](../테스트/))

## 8. 동의어 · 약어 사전

**하이브리드 검색이 필요한 이유가 여기 있습니다.**

| 정식 명칭 | 사내에서 실제로 쓰는 말 |
| --- | --- |
| 연차휴가 | 연차, 연차유급휴가, annual leave, 쉬는 날 |
| 육아휴직 | 육휴, 출산육아휴직, parental leave |
| 재택근무 | 원격근무, 리모트, WFH |
| 법인카드 | 회사카드, **법카** |
| 성과급 | 인센티브, PS, 보너스 |
| 퇴직연금 | DC, DB, IRP |
| 회의실예약 | 미팅룸 예약, 회의실 잡기 |

```
   "법카 정산 어떻게 해요?"

   BM25   «법카» 라는 토큰이 문서에 없다 → 못 찾는다
   벡터   «법인카드 경비정산» 문서와 의미가 가깝다 → 찾는다
   ────────────────────────────────────────────────
   → 벡터 검색이 필요한 이유

   "연차휴가 한도가 며칠인가요?"

   벡터   «15일»과 «25일» 문서가 의미 공간에서 거의 같은 위치 → 구분 못 한다
   BM25   «한도», «일수» 토큰의 정확 일치로 기준표를 찾는다 → 찾는다
   ────────────────────────────────────────────────
   → 키워드 검색이 필요한 이유
```

> 두 방식의 **실패 지점이 다릅니다.** 그래서 합쳐야 합니다.
> 이것이 «하이브리드»의 근거이며, [설계/06](../설계/06_Hybrid_검색_설계서.md) 에서 수치로 확인합니다.
