# 04. 데이터 소스 분석 — 1만 건 이상 샘플 코퍼스 설계

> **목적** — 왜 «가상 데이터»를 만들어야 하는지, 그리고 그것이 **RAG 검증에 쓸 만하려면 무엇을 갖춰야** 하는지 정합니다.

## 1. 왜 실제 사내 문서를 쓰지 않는가

| 이유 | 설명 |
| --- | --- |
| **개인정보** | 인사 문서에는 사번·이름·연락처·평가 등급이 섞여 있다. 실습·실험에 쓸 수 없다 |
| **기밀** | 급여 테이블·징계 이력은 유출 시 회복 불가 |
| **정답 라벨 부재** | 실제 문서로는 «이 질문의 정답이 어느 문서인지»를 손으로 라벨링해야 한다 |
| **재현 불가** | 문서가 계속 바뀌어 «어제와 오늘의 실험»을 비교할 수 없다 |
| **함정 부재** | 실제 코퍼스에 «버전 충돌»이 마침 있을지 알 수 없다 |

> 🔑 **가상 데이터의 진짜 장점은 «정답을 미리 안다»는 것입니다.**
> 생성 시점에 «이 문서가 이 질문의 정답»이라고 심어 두면, 라벨링 없이 평가 세트가 만들어집니다.

### 1.1 가상 데이터의 한계 — 정직하게

| 한계 | 영향 | 완화 |
| --- | --- | --- |
| 실제 문장 다양성이 부족하다 | 템플릿 흔적이 남는다 | 의도·수식어·수치를 조합해 변형 |
| 실사용 질의와 다르다 | 평가가 낙관적일 수 있다 | 실제 문의 로그로 평가 세트 재구성 필요 |
| 도메인 지식의 «미묘함»이 없다 | 어려운 사례가 덜 어렵다 | 함정을 의도적으로 심어 보완 |
| 임베딩 모델의 사전 지식과 어긋날 수 있다 | 벡터 성능이 실제와 다를 수 있다 | Azure 임베딩으로 재측정 필요 |

> ⚠️ **이 코퍼스로 잰 수치는 «전략 간 상대 비교»에 쓰고,
> «운영 품질의 절대 예측»에는 쓰지 않습니다.**

## 2. 코퍼스 설계 원칙

```
   ① 다양성   문서 «유형»이 달라야 한다 (청킹 전략이 유형별로 갈리므로)
   ② 분포     길이가 현실을 닮아야 한다 (짧은 FAQ 다수 + 긴 규정 소수)
   ③ 함정     틀리기 쉬운 경우가 «의도적으로» 들어 있어야 한다
   ④ 메타     필터로 쓸 만한 메타데이터가 있어야 한다
   ⑤ 정합성   질문과 답이 «실제로» 맞아야 한다
   ⑥ 재현성   같은 시드는 같은 코퍼스를 만들어야 한다
   ⑦ 안전     실재하는 사람·회사·금액이 없어야 한다
```

### 2.1 ⑤ «정합성»에서 실패했다가 고친 기록

처음에는 질문 패턴과 답변 형태를 **무작위로 조합**했습니다. 결과:

```
   Q. 연차휴가 사용하면 불이익이 있나요?
   A. 연차휴가의 기준은 8시간입니다. 수석 이상은 29시간까지 가능하며…
      └─ 질문에 답하지 않는다
```

이러면 «검색이 옳은 문서를 찾았는가»를 판정할 수 없습니다. **정답이 실제로 답이어야** 평가가 성립합니다.

→ 질문을 **의도(intent)** 로 묶고, 의도가 같은 답변 형태만 붙이도록 고쳤습니다.

| 의도 | 질문 예 | 답변이 담아야 할 것 |
| --- | --- | --- |
| 절차 | "어떻게 신청하나요?" | 시스템·메뉴·결재선·순서 |
| 수치 | "며칠까지 가능한가요?" | 숫자·단위·직급별 차등 |
| 승인자 | "승인 권한은 누구에게?" | 결재자·예외 조건 |
| 기한 | "언제까지 신청하나요?" | 기한·초과 시 처리 |
| 서류 | "필요 서류가 무엇인가요?" | 서식·증빙 목록 |
| 담당 | "담당 부서가 어디인가요?" | 부서·채널·시간 |
| 변경 | "제도가 바뀐 게 있나요?" | 변경 전후·시행일 |
| 반려 | "왜 반려됐나요?" | 반려 사유·재신청 |
| 가부 | "예외 인정되나요?" | 가능/불가 + 조건 |
| 불이익 | "쓰면 불이익 있나요?" | 없음 + 근거 |
| 소요기간 | "얼마나 걸리나요?" | 영업일 수 |

### 2.2 ⑦ «안전»을 위해 한 일

| 요소 | 처리 |
| --- | --- |
| 회사명 | **누리컴퍼니** — 가상 |
| 도메인 | `intranet.nuri.example` — RFC 2606 예약 도메인 |
| 사번 | `EMP-#####` — 실재하지 않는 패턴 |
| 이름 | **사용하지 않음** (부서명·직급만) |
| 연락처 | 내선 번호만, 외부 전화번호 없음 |
| 금액·일수 | 무작위 생성. 실제 사규와 무관 |
| 규정 조항 | 실제 근로기준법 조문을 인용하지 않음 |

## 4. 의도적으로 심은 «함정» (34건)

평가 세트는 **함정에서 역으로** 만듭니다. 정답 문서 ID 를 생성 시점에 알고 있으므로 라벨링이 정확합니다.

| 함정 | 건수 | 무엇을 검증하는가 |
| --- | ---: | --- |
| **버전 충돌** | 10 | 폐지된 구버전이 현행보다 위에 오지 않는가 |
| **근사 중복** | 6 | 인사규정·취업규칙의 동일 문장이 상위를 독점하지 않는가 |
| **숫자 정밀도** | 5 | 「15일」과 「25일」을 구분하는가 |
| **다중 홉** | 9 | 2~3개 문서를 모두 찾는가 |
| **권한 제한** | 4 | 제한 문서가 일반 사용자에게 노출되지 않는가 |

### 4.1 버전 충돌 함정의 구조

```
   TRP-00001  [폐지] 연차휴가 운영기준 v1.0
              한도 연 10일 · 신청 7일 전
              effective 2023-01-01 · expiry 2025-12-31 · status 폐지

   TRP-00002  [현행] 연차휴가 운영기준 v2.0     ← 정답
              한도 연 20일 · 신청 3일 전
              effective 2026-01-01 · status 현행
```

같은 주제·비슷한 제목·다른 숫자. **틀린 답이 그럴듯합니다.**

### 4.2 다중 홉 함정의 구조

```
   질문  "3년차 개발직이 육아휴직을 쓰면 급여와 평가는 어떻게 되나요?"

   조각 ① 육아휴직 급여 처리     (인사>휴직)
   조각 ② 휴직자 인사평가 처리   (인사>평가)   ← 다른 중분류에 있다
   조각 ③ 육아휴직 신청 자격     (인사>휴직)

   → 한 문서로는 답할 수 없다. 셋을 모두 찾아야 «완전한 답»이 된다.
```

## 5. 실제 도입 시 데이터 소스 (참고)

이 프로젝트는 가상 데이터를 쓰지만, 실제 구축에서는 다음이 소스가 됩니다.

| 소스 | Azure 연결 방법 | 주의 |
| --- | --- | --- |
| SharePoint 문서고 | 인덱싱된 SharePoint 지식 원본 (미리 보기) | 권한 동기화 확인 |
| Blob Storage | Blob 지식 원본 / 인덱서 | 가장 단순 |
| Confluence·Notion | 커스텀 커넥터 또는 내보내기 | 표·첨부 처리 |
| 그룹웨어 게시판 | API 추출 → Blob | 개인정보 마스킹 필수 |
| 문의 티켓(Jira 등) | API 추출 → Blob | **개인 식별 정보 제거** |
| 사규 PDF | Document Intelligence + Blob | 표·레이아웃 추출 |

### 5.1 실제 문서로 옮길 때 반드시 할 일

```
   ① 개인정보 제거      이름·사번·연락처·평가등급 마스킹
   ② 권한 매핑          문서의 접근 권한을 security_level 로 변환
   ③ 상태 판정          폐지·개정 문서를 status 로 표시  ← 대부분 여기서 막힌다
   ④ 유형 분류          규정/지침/FAQ 구분              ← 자동 분류가 어렵다
   ⑤ 평가 세트 재구성   실제 문의 로그에서 질의 추출
```

> ⚠️ **③과 ④가 실제 프로젝트에서 가장 오래 걸립니다.**
> 많은 조직이 «어느 문서가 현행인지»를 시스템으로 관리하지 않습니다.
> 이 정보가 없으면 버전 충돌을 막을 방법이 없습니다.
> → RAG 구축 이전에 **문서 거버넌스**가 필요하다는 결론이 나오기도 합니다.

### 6.1 한국어 조사 처리를 별도로 만든 이유

템플릿으로 문장을 만들면 `육아휴직은(는)`, `부문장이(가)` 같은 표기가 남습니다. 사람이 읽기 나쁠 뿐 아니라:

| 문제 | 영향 |
| --- | --- |
| `은(는)` 은 실제 한국어에 없는 토큰 조합 | 토크나이저가 이상하게 쪼개 **문장 벡터가 왜곡**된다 |
| `접대비은(는)` ≠ `접대비` | **BM25 재현율이 떨어진다** |

> 합성 데이터라도 **언어적으로 정상**이어야 실험 결과를 믿을 수 있습니다.
> 받침 유무(종성 인덱스)로 조사를 확정하고, 숫자·영문의 «읽는 소리»까지 처리했습니다.
> 검증: 미해결 표기 **0건**
