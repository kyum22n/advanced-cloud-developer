**수동으로 확인하려면**

```powershell
# 로그인·구독
az account show -o table

# GPU 쿼터 — 0 이면 신청이 필요하다
az vm list-usage --location koreacentral -o table | Select-String -Pattern "NC|ND|NV"

# 해당 리전에 SKU 가 있는지
az vm list-skus --location koreacentral --resource-type virtualMachines -o json |
  ConvertFrom-Json | Where-Object { $_.name -eq $env:GLM_SKU } |
  Select-Object name, @{n='restrictions';e={$_.restrictions.Count}}
```

> ⚠️ **GPU 쿼터는 기본값이 0인 경우가 많고, 승인에 수 시간~수 일이 걸립니다.** 실습 일정이 있다면 **가장 먼저** 신청하세요.
> Azure Portal → 구독 → **사용량 + 할당량** → 해당 GPU 제품군 → 증가 요청.
>
> 📌 **Spot 쿼터는 온디맨드 쿼터와 별개입니다.** Spot 을 쓰려면 «Standard NCADSA100v4 Family vCPUs» 와 함께 **Spot vCPU 쿼터**도 확인하세요.

## 2. 20 구성 — 노드 풀 · 저장소 · 신원

```powershell
pwsh -File .\20_config.ps1
```

**이 단계가 하는 일 (의존 순서)**

```
1 리소스 그룹·태그
  → 2 Storage(가중치) + Key Vault
  → 3 관리 ID + 역할 부여(Storage Blob Data Reader · Key Vault Secrets User)
  → 4 GPU 노드 풀 추가(Spot · taint · min 0)
  → 5 OIDC 연합 자격 증명(glm-sa)
  → 6 네임스페이스·SA·SecretProviderClass 적용
```

**핵심 명령**

```powershell
# GPU 노드 풀 — taint 와 min-count 0 은 세트다
az aks nodepool add -g $RG --cluster-name $AKS -n gpu `
  --node-vm-size $SKU --node-count 0 `
  --enable-cluster-autoscaler --min-count 0 --max-count 4 `
  --priority Spot --eviction-policy Delete --spot-max-price -1 `
  --node-taints "sku=gpu:NoSchedule" --labels workload=llm `
  --node-osdisk-type Ephemeral --mode User `
  --tags workload=llm model=glm5.2 env=prd

# 가중치 저장소 — 공유 키를 끄고 RBAC 로만 접근한다
az storage account create -g $RG -n $SA_NAME -l $LOC `
  --sku Standard_LRS --kind StorageV2 --min-tls-version TLS1_2 `
  --allow-shared-key-access false

# 관리 ID 에 «읽기» 역할만 부여한다
az role assignment create --assignee-object-id $PRINCIPAL_ID `
  --assignee-principal-type ServicePrincipal `
  --role "Storage Blob Data Reader" --scope $STORAGE_ID

# 워크로드 ID 연합 — subject 형식은 정확해야 한다
az identity federated-credential create -g $RG --identity-name id-glm-prd -n fc-glm `
  --issuer $OIDC --subject "system:serviceaccount:glm-serving:glm-sa" `
  --audiences api://AzureADTokenExchange
```

> 🔑 **`Storage Blob Data Reader`(읽기 전용)만 부여합니다.** 서빙 파드는 가중치를 **읽기만** 하면 됩니다. 쓰기 권한을 주면 침해 시 모델이 교체될 수 있습니다.

## 3. 가중치 업로드 — 한 번만

```powershell
# ① 모델을 내려받는다 (라이선스 동의 후)
#    HF 토큰이 필요하면 Key Vault 에 저장하고 환경 변수로 주입한다
huggingface-cli download <org>/<model> --local-dir .\weights\<model>

# ② Blob 에 업로드 (로그인 계정의 Entra 권한으로 — 계정 키를 쓰지 않는다)
az storage blob upload-batch `
  --account-name $SA_NAME --auth-mode login `
  --destination models --destination-path <model> `
  --source .\weights\<model> --overwrite
```

| 계층 선택 | 언제 |
| --- | --- |
| **Hot** | 노드가 자주 새로 뜬다(Spot·scale-to-zero) — **다운로드가 잦음** |
| Cool | 노드가 오래 유지된다 — 저장 비용 우선 |

> ⚠️ **`--auth-mode login` 을 쓰세요.** 계정 키를 쓰면 «공유 키 비활성화» 설정과 충돌하고, 키가 셸 히스토리에 남습니다.

## 5. 40 배포 — 모델 로딩을 기다린다

```powershell
pwsh -File .\40_deploy.ps1
```

```powershell
kubectl apply -k config\k8s

# 노드가 새로 뜨고 가중치를 로딩하므로 오래 걸린다
kubectl rollout status deploy/glm -n glm-serving --timeout=1800s

# 진행 상황을 지켜본다
kubectl get pods -n glm-serving -w
kubectl logs -n glm-serving -l app=glm -f
```

**단계별로 무엇을 보는가**

| Pod 상태 | 의미 | 정상 소요 |
| --- | --- | --- |
| `Pending` | **GPU 노드를 기다리는 중** | 2~4분 |
| `ContainerCreating` | 이미지 pull | 1~3분 |
| `Running` (Ready 0/1) | **가중치 로딩 중** | 2~10분 |
| `Running` (Ready 1/1) | 서빙 준비 완료 | – |

> ⚠️ **`Pending` 이 5분 넘게 지속되면 노드가 안 뜨는 것입니다.**
> ```powershell
> kubectl describe pod -n glm-serving -l app=glm | Select-String -Pattern "Insufficient|FailedScheduling|taint"
> az aks nodepool show -g $RG --cluster-name $AKS -n gpu --query "{count:count,min:minCount,max:maxCount}" -o json
> ```
> 흔한 원인: **GPU 쿼터 부족** · Spot 재고 없음 · toleration 누락 · `nvidia.com/gpu` 미노출([04 §3](04_배포_설계.md)).

## 10. 문제 해결

| 증상 | 원인 | 조치 |
| --- | --- | --- |
| 파드 `Pending` 지속 | GPU 쿼터·Spot 재고·taint 불일치 | `describe pod` 의 이벤트 확인 → §1 쿼터 |
| `nvidia.com/gpu` 가 0 | 드라이버·디바이스 플러그인 미설치 | [04 §3](04_배포_설계.md) |
| 무한 재시작(CrashLoop) | **`startupProbe` 가 너무 짧다** | 실패 허용 횟수를 늘린다([04 §4](04_배포_설계.md)) |
| OOM(CUDA out of memory) | VRAM 부족 | 양자화 · `--max-model-len` 축소 · `--gpu-memory-utilization` 조정 |
| 텐서 병렬 실패 | **`/dev/shm` 부족** | `emptyDir(medium: Memory)` 8Gi 이상 |
| 첫 응답이 매우 느림 | 콜드 스타트 | 노드 캐시 · 최소 1대 상시 검토 |
| Spot 회수 잦음 | 리전 수요 | 다른 리전·SKU · 온디맨드 비중 상향 |
| Blob 접근 거부 | 역할 전파 지연·subject 오타 | 역할 확인 · `federated-credential list` 대조 |
| 앱에서 접속 불가 | NetworkPolicy · 주소 오타 | `LLM_BASE_URL` 확인 · 정책 확인 |
