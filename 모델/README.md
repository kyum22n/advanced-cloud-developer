| 폴더 | 모델 | 상태 |
| --- | --- | --- |

---

## 2. 앱 배포(`배포/`)와의 관계

| | `배포/` (앱) | `모델/` (LLM) |
| --- | --- | --- |
| 대상 | 업무 앱 (Node/Java/Python) | 추론 서버 (vLLM) |
| 컴퓨트 | CPU 노드 풀 | **GPU 노드 풀 (Spot · taint · min 0)** |
| 비용 지배 요인 | 노드 수 · PaaS | **GPU 시간 (90%+)** |
| 상태 | PostgreSQL | **모델 가중치 (Blob)** |
| 신원 | 워크로드 ID | **워크로드 ID (동일)** |
| 9단계 스크립트 | `10_prereq ~ 90_cleanup` | **동일한 이름 · 동일한 흐름** |

> 🔑 **의도적으로 같은 구조를 씁니다.** 앱 배포에서 익힌 절차·보안 규칙·검증 방식을 그대로 옮길 수 있어야, 모델 배포가 «완전히 다른 세계»가 되지 않습니다.

---

## 3. 공통 원칙 (앱과 동일)

| 원칙 | 앱에서 | 모델에서 |
| --- | --- | --- |
| 비밀을 만들지 않는다 | Key Vault + 워크로드 ID | **저장소 키 대신 워크로드 ID** |
| 설정은 주입한다 | ConfigMap/Secret | ConfigMap + Key Vault CSI |
| 이미지 태그는 불변 | `prd-<sha>` | **vLLM 버전 고정 · `latest` 금지** |
| 검증은 «작동한다»를 본다 | P-21 파드 토큰 주입 | **G-S-03b 파드 토큰 주입** |
| 정리는 필수 | `90_cleanup.ps1` | **GPU 는 방치 시 가장 비싸다** |
